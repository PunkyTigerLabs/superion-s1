# Superion S1 — OpenAPI 3.1 specification

Machine-readable description of the **Superion S1** API by Punky Tiger Labs
(`https://api.punkytigerlabs.com`): `POST /v1/systemone`, `GET /v1/models`, `GET /v1/usage`,
`POST /v1/keys/rotate`, `POST /v1/keys/revoke`, `GET /health`, with every error (400, 401, 402,
413, 422, 429, 503), rate-limit headers and real examples.

Files: [`superion-s1.yaml`](superion-s1.yaml) (full) and
[`superion-s1.marketplace.yaml`](superion-s1.marketplace.yaml) (for resellers and API gateways:
only `/v1/systemone`, `/v1/models` and `/health`, generated by `scripts/make_marketplace_spec.py`).

Use it to:

* import the API into **Postman**, **Insomnia**, **Bruno** or **AWS API Gateway**;
* generate clients (`openapi-generator`, `openapi-typescript`, `oapi-codegen`…);
* render docs (`npx @redocly/cli build-docs superion-s1.yaml`).

Official SDKs: `pip install superion-s1` · `npm i @punkytigerlabs/superion-s1`.

## Validation

```bash
pip install openapi-spec-validator pyyaml jsonschema pytest
openapi-spec-validator superion-s1.yaml
npx @redocly/cli@2.78.0 lint superion-s1.yaml        # uses redocly.yaml
pytest tests                                                 # spec + real responses vs. schemas
S1_LIVE=1 SUPERION_API_KEY=s1k_... pytest tests              # + live /health, /v1/models, one decision
```

The tests check that the documented examples and a real v6 response captured on 12 Nov 2026 validate
against the schemas, and that requests the API rejects (17 score levels, 1 choice option, bad noul
criteria, unknown type, no questions) are also rejected by the schema.

## Notes

* `model` is required. Model IDs are immutable; `GET /v1/models` lists what is served.
* Prepaid responses carry `X-RateLimit-*` (per minute) and `X-S1-Balance-USD`; Free responses carry
  `X-RateLimit-*-Day`. 429 and 503 carry `Retry-After`.
* Server-to-server only: `/v1/systemone`, `/v1/usage` and `/v1/keys/*` send no CORS headers.
